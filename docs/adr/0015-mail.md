# ADR 0015 — Mail

**Status:** accepted · **Date:** 2026-09-21 · **Phase:** 6 (first slice)

## Context

Five phases built a service that registers a user and tells nobody. The
roadmap listed mail under "beyond, unscheduled" with the rule that a subsystem
gets a number when something needs it. The template's registration is the
caller: a welcome on sign-up is the smallest real message a service sends, and
the password reset the template declines needs the same seam before it can
exist. Laravel's `Mail` facade is the reference, as it was for the cache and
the queue: one call, a driver behind it, a fake that records.

## Decisions

### 1. The shape transfers whole

`keel.mail` is ADR 0001's shape without variation: a `Mailer` protocol with
`send` and `close`, drivers behind it, a `MailManager` that builds them from a
frozen `MailConfig`, a `Binding` with a process default and a context override,
`mail_lifespan` to bind one, and `send()` as the facade. The token store (ADR
0007) had already shown the shape fits a subsystem with no cache semantics; mail
is the third time it has been applied unchanged, which is the evidence it is a
shape and not a coincidence.

`send()` is a **Virtual Proxy** over the bound mailer, the role `dispatch()`
plays for the queue. It fills the configured sender into a message that named
none, and announces a `MailSent` event on the manager's dispatcher with the
driver, the recipient count, the subject and the message id — never a body or
an address. Nothing in Keel listens yet; the seam is there so a listener that
counts mail is an application's to write without any driver knowing observers
exist.

### 2. A message is a value object, validated once

`Message` is frozen and checked on construction, and it is the only thing a
mailer accepts. Two rules live there rather than in a driver, so the SMTP
mailer, the logging one and the recording fake all refuse the same input: a
message must have a recipient, and no address, subject or custom header may
contain a line break. The second is header injection: an address followed by a
newline and `Bcc:` is one more recipient, typed into a form field. A driver
that checked it would be one driver; the fake that did not would be a test
suite that passes on input production refuses.

`headers=` may not name a header the message writes itself — `To`, `Bcc`,
`Subject`, `Message-ID` and the rest of `RESERVED_HEADERS`. The review put a
`Bcc` through it and watched it go on the wire; a second `To` made one driver
raise a bare `ValueError` while three others delivered.

Rendering is the standard library's `EmailMessage`, which gets encoding,
multipart alternatives and header folding right. Text is mandatory and HTML is
an alternative to it, never a replacement. `Bcc` recipients reach the envelope
and never the headers. Every driver renders, the fake and the logging one
included, and throws the result away: a message SMTP could not send fails the
test that thought it had sent it, and a driver handed a senderless message
around the facade refuses it whichever driver it is.

### 3. SMTP from the standard library, on a worker thread

`smtplib` under `anyio.to_thread.run_sync`, exactly as Argon2 is run. One
connection per message, closed afterwards. An async SMTP client was declined
because its value is a pooled, pipelined connection, which a service that sends
a welcome and a reset does not need; a connection held open across messages has
to survive the server's idle timeout, and the code to notice that it did not is
larger than the connect it saves. `MAIL_SECURITY` is `none`, `starttls` or
`tls`, refused at construction if anything else, so a typo fails at start-up.

A refusal raises `MailDeliveryError` naming the host and port and the refused
recipients, with `permanent` set when the server's answer was a 5xx: a job
that sends retries a timeout or a 4xx with backoff and stops on a 5xx, which
the template's welcome job does by converting one to `PermanentFailureError`.
A server that refuses some recipients after accepting the rest has sent the
mail, so that is reported on the `Delivery` — `recipients` is who got it,
`refused` is who did not and why — rather than raised. The first draft raised,
and the review's stub server showed the accepted recipient receiving a copy
per retry, five before the job dead-lettered.

The `Message-ID` is minted from the address inside the sender, parsed, so a
`MAIL_FROM` of `Acme <noreply@acme.example>` yields an id ending in
`@acme.example>` and not `@acme.example>>`, which the server would silently
truncate into a different id from the one logged.

### 4. Four drivers, one contract suite, and where the fake lives

`smtp`, `log`, `null` and `fake`. `MAIL_SECURITY=none` with credentials is
refused at construction: the password would cross the network in clear, and a
relay that wants a login can offer STARTTLS. `log` writes who was mailed about what — the
recipients, the sender, the subject, the message id — and never a body, so a
staging environment with no server still shows that registration mails. `null`
is the documented Null Object, for a process that must never send, and is
excluded from the contract suite rather than allowed to weaken it. `fake`
records every message and answers `assert_sent`, `assert_sent_times` and
`assert_nothing_sent` with the timeline of what was sent in the failure
message.

The suite is parametrised over `smtp`, `log` and `fake`, and the SMTP cases run
against Mailpit, reading the message back through its API so the assertion is
on what arrived: the alternative parts, the folded subject, the absent `Bcc`
header. They skip when Mailpit is not answering, like every service-backed
test, and `just doctor` now says whether it is. Refusals are tested against a
stub SMTP server in the suite that answers per recipient, since Mailpit
accepts everything.

### 5. The template sends from a seam that waits for the commit

Registration builds the welcome in `modules/users/mail.py`, one function per
message, and sends it from the same seam a job dispatch uses. With a worker,
`create_user` dispatches `SendWelcome` inside the unit of work; the queue pushes
it only once the transaction commits (ADR 0006). Without one, it registers the
send with `after_commit`, the hook `dispatch()` itself uses. Either way a row
that rolls back welcomes nobody, and the test that proves it registers a
duplicate address and asserts the outbox is empty.

The after-commit path had a hole the review found: `run_after_commit` swallowed
a callback's exception unless the application passed a handler, no generated
project passed one, and so a welcome the server refused — or every welcome,
under a `MAIL_*` left unset in production — vanished with the 201 already
sent. A failing after-commit callback, and a failing model observer, are now
logged on `keel.database` with the traceback by default; the handlers remain
for an application that wants them elsewhere. The generated api-shape suite
points the mailer at a port nothing listens on and asserts the log line.

The job carries the account's public identifier, not the address. An account
that changed its email before the worker reached the job is welcomed at the
current one; one deleted meanwhile raises `PermanentFailureError` and is not
retried.

Mailpit runs beside Postgres and Redis under `just up`, and the app containers
point at it. Every message a development run sends is at its web UI, and
nothing leaves the machine. The generated suite sets `MAIL_DRIVER=log` so it
needs no Mailpit, and the tests that ask what was sent enter `fake_mail()`.

## What was declined

| Declined | What would change it |
|---|---|
| A template engine, or a `Mailable` class with a `build()` step | A second message whose layout the first should share. That message was the password reset, two days later: `keel.mail.templates` is the result, and [ADR 0016](0016-password-reset.md) records it. The `Mailable` stays declined. |
| A queue inside the mail subsystem (`Mail::queue`) | Nothing: the queue exists, and a job that calls `send()` is the whole feature. A second path into the queue would be two ways to say "later". |
| An async SMTP client, connection pooling | Decision 3. A process sending thousands of messages a minute. |
| Attachments | No caller. `EmailMessage.add_attachment` is one line when one arrives, and `Message` carries `headers` for anything a provider needs meanwhile. |
| A driver for a provider's HTTP API: SES, Postmark, Resend | Every one of them accepts SMTP, so each works today through `MAIL_HOST`. Their HTTP APIs add batching and provider-side templates this does not use; a driver arrives with the deployment that needs one. |
| Address parsing and validation | A newline is refused and nothing else is judged: what counts as a deliverable address is the server's decision, and the SMTP driver reports its answer per recipient. |
| Rate limiting outbound mail | Belongs with rate limiting, still unscheduled. |
| A readiness check on the mail server | No request needs it to answer, and a probe on it would pull the API out of rotation for a dead relay. ADR 0010 sends that class of fact to metrics. |

## Consequences

**`MAIL_DRIVER` defaults to `log` in the library and `smtp` in the template.**
The library cannot assume a server; the template ships one.

**Sending inside a request costs a connection.** For the API-only shape the
welcome runs after the commit, on the request, against Mailpit or whatever the
deployment points at. A slow server slows registration. That is the price of
having no worker, and the reason the `both` shape is the recommended one.

**A `MailSent` event names a subject.** Subjects are the application's own
strings and not user input in the template; a service that puts user-supplied
text in a subject should know it reaches the dispatcher's listeners.

**After-commit failures are loud now, everywhere.** The default changed for
every after-commit callback and every model observer, not only mail: a queue
that was unreachable when a dispatch tried to push used to disappear the same
way. A deployment that routed nothing sees new `ERROR` lines that were always
true.

## What the review caught

Ten findings, the SMTP ones reproduced against Mailpit and a stub server:

- **A refused welcome vanished in the api-only shape**: no log, no metric.
  Decision 5.
- **`headers={"Bcc": ...}` went on the wire**, and a duplicate `To` raised a
  `ValueError` on one driver of four. Decision 2.
- **A display-name sender minted a `Message-ID` ending `>>`**, so the logged id
  and the delivered one disagreed. Decision 3.
- **A partial refusal re-delivered to the accepted recipients on every retry.**
  Decision 3.
- **Drivers disagreed on a senderless message**, and the contract suite could
  not see it because every case had a sender. Decision 2.
- **`MAIL_SECURITY=none` with credentials was accepted.** Decision 4.
- **A failed STARTTLS handshake left the socket to the garbage collector.**
  Closed on the way out now.
- **The SMTP import deferred in `_make` was re-exported eagerly one file up.**
  Ceremony; the deferral went.
- **The generated `runtime` fixture opened every lifespan but mail's**, while
  claiming to mirror the entrypoint. It opens it.
- **Docstrings that pointed at a test file that did not exist, a claim that
  metrics counted mail, `MAIL_TIMEOUT` missing from `.env.example`, and
  `just doctor` not knowing Mailpit existed.**

## Verification

- `test_a_message_that_cannot_be_sent_is_refused_on_construction` — decision
  2: no recipient, and a line break in an address, the subject, a custom
  header, before any driver is involved.
- `test_as_mime_renders_alternatives_headers_and_no_bcc` — decision 2.
- `test_smtp_delivers_the_message_mailpit_shows` — decision 3, read back from
  Mailpit: the alternative parts, the headers, the envelope.
- `test_an_unreachable_server_is_a_delivery_error` — decision 3, naming the
  host and port.
- `test_a_partial_refusal_is_delivered_to_the_rest_and_reported` and
  `test_a_refusal_of_every_recipient_says_whether_a_retry_can_help` — decision
  3, against the stub server.
- `test_a_display_name_sender_still_mints_a_matching_message_id` — decision 3,
  the id Mailpit reports compared exactly.
- `test_a_message_with_no_sender_is_refused_by_every_driver` — decision 2, in
  the contract suite.
- `test_a_failing_after_commit_callback_is_logged_by_default` — decision 5, in
  the dispatch suite; and generated,
  `test_a_welcome_the_server_refuses_is_logged_not_raised`.
- `test_the_log_mailer_writes_the_envelope_and_never_the_body` — decision 4.
- `test_send_fills_in_the_configured_sender_and_announces` — decision 1.
- `test_the_override_wins_over_the_process_wide_binding` — the binding's
  context override, so concurrent tests cannot see each other's outbox.
- Generated: `test_registration_dispatches_a_welcome` or
  `test_registration_sends_a_welcome`, and
  `test_a_registration_that_fails_sends_nothing` — decision 5.
